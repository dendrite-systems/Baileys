# Strawberry JavaScript fork

Based on WhiskeySockets/Baileys `v7.0.0-rc14` at
`7e7b0757e3f9f3c7789fb1cfd2f241d5002a199a`. The original MIT license and attribution apply.

The runtime uses TypeScript/JavaScript and platform-provided cryptography. It does not
ship `whatsapp-rust-bridge`, WebAssembly, Sharp, or an image-processing native addon.
MD5 and HKDF use `node:crypto`; app-state key expansion and the additive integrity hash
retain the upstream wire format. Existing Signal sessions still use upstream `libsignal`.

Image processing is optional: install `jimp` for thumbnails and profile pictures. Text
messaging, QR pairing, and history sync do not require it. Video thumbnail generation
still requires an external FFmpeg executable; that path is not Worker-compatible.

The fork includes the pre-login acknowledgement and companion registration refresh fixes.
They allow an unpaired connection to acknowledge notifications and refresh the advertised
pairing secret without consuming another QR reference or extending its expiration.

## Cloudflare transport

Use Workers with `nodejs_compat` and supply the transport explicitly:

```ts
import makeWASocket, { CloudflareWebSocketClient } from '@dendrite-systems/baileys'

const socket = makeWASocket({
  auth, // Application-owned credential and Signal key storage.
  logger,
  createWebSocket: (url, config) => new CloudflareWebSocketClient(url, config)
})
```

The default transport remains Node's `ws`. The Cloudflare adapter uses a fetch upgrade
to preserve the WhatsApp Origin header and closes locally without waiting indefinitely
for the peer's close acknowledgement. Node proxy agents are not supported by this adapter.

An application must own one active connection per linked account, persist credential/key
updates securely, and reconnect after process or Durable Object eviction. This library
does not provide that hosting lifecycle. File-based auth helpers and FFmpeg media paths
are for Node, not Workers. A successful pairing-QR probe is not proof that a user's account
has linked or that all media operations work in Workers.

## Verification and maintenance

```sh
corepack yarn install --immutable
corepack yarn lint
corepack yarn test --runInBand
corepack yarn build
corepack yarn test:live-pairing
```

The live pairing test contacts WhatsApp, performs the real protocol handshake, checks that
a QR is issued, and closes. It does not link an account or send messages. Full account linking,
history, reconnect, and message delivery additionally require an explicitly selected test
account and a phone scan. Upstream `test:e2e` requires access to the private Bartender image.

The committed synthetic fixtures were generated by `whatsapp-rust-bridge@0.5.4` and the
upstream release. They cover integrity hashing and authenticated app-state patch decoding.
Keep the RFC crypto vectors and mutation authentication tests when merging upstream updates.
Compare changed wire-level behavior against upstream before releasing another fork version.

Consumers should pin a versioned package artifact with lockfile integrity, not a moving branch.
