# Strawberry JavaScript fork

Based on WhiskeySockets/Baileys `v7.0.0-rc14` at
`7e7b0757e3f9f3c7789fb1cfd2f241d5002a199a`. The original MIT license and attribution apply.

The runtime uses TypeScript/JavaScript and platform-provided cryptography. It does not
ship `whatsapp-rust-bridge`, WebAssembly, Sharp, or an image-processing native addon.
MD5 and HKDF use `node:crypto`; app-state key expansion and the additive integrity hash
retain the upstream wire format. Existing Signal sessions still use upstream `libsignal`.

Image processing is optional: install `jimp` for thumbnails and profile pictures. Text
messaging, QR pairing, and history sync do not require it. Video thumbnail generation
still requires an external FFmpeg executable; that path is not Worker-compatible.

The fork includes the pre-login acknowledgement and companion registration refresh fixes.
They allow an unpaired connection to acknowledge notifications and refresh the advertised
pairing secret without consuming another QR reference or extending its expiration.

## Cloudflare transport

Use Workers with `nodejs_compat` and supply the transport explicitly:

```ts
import makeWASocket, { CloudflareWebSocketClient } from '@dendrite-systems/baileys'

const socket = makeWASocket({
  auth, // Application-owned credential and Signal key storage.
  logger,
  createWebSocket: (url, config) => new CloudflareWebSocketClient(url, config)
})
```

The default transport remains Node's `ws`. The Cloudflare adapter uses a fetch upgrade
to preserve the WhatsApp Origin header and closes locally without waiting indefinitely
for the peer's close acknowledgement. Node proxy agents are not supported by this adapter.
Selecting this transport also uses
protobufjs's portable writer throughout its shared module instance. This preserves the wire
bytes while avoiding [workerd's Buffer string-writing bug](https://github.com/cloudflare/workerd/issues/6875);
it does not modify the global Buffer implementation.

An application must own one active connection per linked account, persist credential/key
updates securely, and reconnect after process or Durable Object eviction. This library
does not provide that hosting lifecycle. File-based auth helpers and FFmpeg media paths
are for Node, not Workers. A successful pairing-QR probe is not proof that a user's account
has linked or that all media operations work in Workers.

## Verification and maintenance

```sh
corepack yarn install --immutable
corepack yarn lint
corepack yarn test --runInBand
corepack yarn build
corepack yarn test:live-pairing
```

The live pairing test contacts WhatsApp, performs the real protocol handshake, checks that
a QR is issued, and closes. It does not link an account or send messages. Full account linking,
history, reconnect, and message delivery additionally require an explicitly selected test
account and a phone scan. Upstream `test:e2e` requires access to the private Bartender image.

The committed synthetic fixtures were generated by `whatsapp-rust-bridge@0.5.4` and the
upstream release. They cover integrity hashing and authenticated app-state patch decoding.
Keep the RFC crypto vectors and mutation authentication tests when merging upstream updates.
Compare changed wire-level behavior against upstream before releasing another fork version.

Consumers should pin a versioned package artifact with lockfile integrity, not a moving branch.

## Compact protobuf bindings

All 498 WhatsApp message types and their wire fields remain available. Protobufjs generates
constructors, enums, defaults, and the unchanged TypeScript declarations. Shared runtime
functions encode, decode, and convert messages using one generated set of field descriptions.
Wire and conversion operations reuse those descriptions; the decoder index holds references,
not another schema copy. The runtime uses protobufjs's existing minimal Reader/Writer and
retains its Long, optional-field, oneof, map, unknown-field, and nesting-limit behavior.
There is no runtime schema parser, reflection graph, dynamic code generation, or new dependency.

This applies the descriptor-driven architecture without switching to protobuf-ts. That switch
would require adapting Baileys' public object API and 23 nonstandard enum definitions. Keeping
the established byte primitives preserves the original schema and avoids translating every
message between two object representations. Single-field presence accessors share closures
by field name; their registration cache is released after initialization.

Regenerate with `corepack yarn gen:protobuf` from the repository root. The generator derives
field numbers, types, map keys, and conversion descriptions from `WAProto.proto`, preserving
wire and JSON property order. It rejects new required/group fields, explicitly unpacked
repeated fields, unsupported map keys/scalars, and explicit defaults until those behaviors
are reviewed. All currently defined fields are supported. Unknown incoming fields continue
to be skipped, and numeric enum values remain open.

Compared with strawberry.3, the packed local Worker probe decreases from 1729.05 to
1112.54 KiB minified (356.47 to 292.21 KiB gzip). The matching unpaired, minified local workerd
harness uses approximately 5.5 MiB JavaScript heap after snapshot-triggered garbage collection,
versus 6.2 MiB previously. A separate schema-only probe with all 498 types retained and 1,000
synthetic text-message roundtrips decreases from 1049.9 to 433.6 KiB minified and from 4.69 to
3.65 MiB warm JavaScript heap. These are local baseline measurements, not connected-account
peak memory, external buffer storage, native process memory, or hosted capacity.

The shared codec trades some CPU for size. A synthetic Node benchmark of 100,000 short-message
create/encode/decode roundtrips takes approximately 425 ms versus 243 ms for strawberry.3
(medians of seven runs). This is not a Cloudflare CPU measurement or a full history-sync workload.

Verification includes 1,120,046 conversion/accessor/wire comparisons and 850,500 decoder
comparisons against the standard generated codecs, with and without Long support. Decoder
cases include malformed/truncated input, unknown tags, explicit lengths, and every field of
all 498 types. Production regression tests cover packed/unpacked values, 64-bit integers,
unknown enums, presence, nested messages, map keys, and nesting limits. The packed release
also passes synthetic Signal encryption/decryption and a real WhatsApp handshake/QR probe in
local workerd. Full phone pairing/history/delivery was not repeated for this optimization.
